## 🛡️ بروتوكول المراجعة الصارمة (Weak Writes → Strong Reviews)

> **الغاية:** لو الموديل الحالي ضعيف — يكتب، لكن **لا يُدمج كود قبل مراجعة موديل أقوى**.
> **القاعدة الحاكمة:** جودة الكود تبدأ من حاجز المراجعة، لا من كفاءة الكاتب.

### العملية الإجبارية لأي تغيير كود:
```
1. الموديل الكاتب (أي كان مستواه) يكتب التغيير
2. الموديل المراجع (أقوى متاح) يراجعه خطوة بخطوة:
   - صحة المنطق
   - اتباع CODE_PATTERNS
   - الأمان (لا أسرار، لا بيانات حساسة)
   - عدم كسر call sites (grep لكل تغيير struct/توقيع)
   - لا unwrap/panic في production
3. الـ tests تُشغَّل على الكود المراجع
4. فقط بعد اجتياز 2+3 → يُدمج ويُسجَّل
```

### قواعد إلزامية:
1. **لا دمج بلا مراجعة** — أي كود يُدمج من غير مراجعة = خرق بروتوكول.
2. **المراجع ليس الكاتب نفسه** — لو موديل واحد فقط، يفصل بخطوة توقف: يقرأ كوده من جديد من منظور المراجع قبل "تم".
3. **التغييرات الصغيرة (سطر/سطرين وغير حساسة)** — مراجعة خفيفة (قراءة + build).
4. **التغييرات الكبيرة أو الحساسة (core/auth/أمان)** — مراجعة كاملة + test كامل + سجل قرار.
5. **المراجع يوقّع التغيير** في الإبلاغ.

## 📜 قاعدة التسجيل الفوري في السجل (CHANGELOG.md)

> **إلزامية:** كل مهمة تنتهي → تسجيل فوري في `CHANGELOG.md` (الأحدث في الأعلى).
> التنسيق الجاهز موجود أعلى CHANGELOG.md — انسخه ولا تخترع.

### مصدر الحقيقة الوحيد (Single Source of Truth):
- **`CHANGELOG.md`** = المصدر الوحيد لتاريخ التغييرات.
- **`EXECUTION_AGENDA.md`** = المصدر الوحيد للخطة (الـ roadmap).
- لو المشروع فيه داشبورد يقرأ بيانات من ملفات TS/JSON → هذه الملفات **مرايا (mirrors)** تُحدث من المصدر، ولا تُحرر يدويًا.

### المزامنة:
1. كل مهمة تنتهي = إدخال فوري في `CHANGELOG.md`.
2. عند إنجاز مهمة من الخطط = عكس الحالة في `EXECUTION_AGENDA.md`.
3. لو في مرايا داشبورد → حدّثها بعد المصدر مباشرة (بنفس الصيغة).
4. **ممنوع** تعديل مرآة بدون تعديل المصدر أولًا.

## 🚨 نظام الأخطاء والتعافي

### لو compile/build error:
```
1. جرب Fix بنفسك — اقرأ الـ error، فهمه، صلحه
2. جرب تاني — لو لسة فشل، دور على حل
3. جرب تالت — لو لسة فشل، سجل الـ error كامل + قف المهمة + بلغ المستخدم
```

### لو runtime error:
```
1. اقرأ الـ log
2. حدد النوع (network? memory? config?)
3. جرب Fix (config, restart, rollback)
4. لو فشلت 3 مرات — بلغ المستخدم
```

### لو مفاتيح/أسرار ناقصة:
```
1. تأكد من ملف الإعدادات المحلي
2. اختبر الـ key
3. لو فشل — بلغ المستخدم "محتاج ... جديد"
```
