## 3. قواعد كتابة الاختبارات

1. **اختبار واحد = سلوك واحد.** لا تجمع حوادث متعددة.
2. **أسماء وصفية:** `test_place_order_updates_balance` لا `test1`.
3. **لا tests تعتمد على الشبكة أو API حقيقية.** استخدم mocks/fakes.
4. **لا tests عشوائية** (إلا للـ chaos/stress — وتعزلهم).
5. **الـ network tests (RPC/API) مفصولة** — تشتغل فقط مع env vars حقيقية.

## 4. معيار النجاح لأي مهمة

| المستوى | الشرط |
|---------|-------|
| **مقبول** | `build/check` ينجح + unit tests تمر |
| **جيد** | + كل الـ tests تمر |
| **ممتاز** | + integration tests للمكون المعني تمر |
| **إنتاج** | + stress/performance test يمر (بعد تغييرات data plane) |

**لا تعلن "✅ تم" إلا عند مستوى "ممتاز" على الأقل.**
