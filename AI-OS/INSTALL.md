# INSTALL — تركيب AI-OS في مشروع جديد

## المدة: ~5 دقائق (مع المثبّت التلقائي)

---

## ⚡ الطريقة التلقائية (المُوصى بها — الأسهل)

```powershell
# داخل مجلد AI-OS نفسه (يعمل منه من أي مكان):
powershell -ExecutionPolicy Bypass -File install.ps1
```

**المثبّت يسألك:**
1. مسار المشروع الجديد (ولو مش موجود → ينشئه)
2. اسم المشروع (افتراضي = اسم المجلد — اضغط Enter للقبول)

**هو يقوم بـ:**
- ينسخ القالب كاملًا (12 ملفًا)
- يستبدل `{{PROJECT_NAME}}` و`{{INSTALL_DATE}}` تلقائيًا
- يتجاوز أي ملف مخصص موجود (لا يكتب فوقه)

**مُختبر فعليًا** — نسخ 12 ملف + استبدال الاسم صحيح.

---

## الطريقة اليدوية (البديلة)

### الخطوة 1 — انسخ القالب داخل مشروعك

```bash
# من داخل مشروعك الجديد:
cp -r path/to/AI-OS/. .
# النتيجة: AGENTS.md, AI_MANDATE.md, RESEARCH_PROTOCOL.md, RESEARCH_LOG.md, EXECUTION_AGENDA.md, TEST_RUNNER.md, CODE_MAP.md, CODE_PATTERNS.md, SECURITY.md
```

---

## الخطوة 2 — استبدل اسم المشروع

استبدل كل `{{PROJECT_NAME}}` باسم مشروعك:

```bash
# Windows PowerShell:
Get-ChildItem AI-OS/*.md | ForEach-Object {
    (Get-Content $_.FullName -Raw) -replace '{{PROJECT_NAME}}', 'My Project' | Set-Content $_.FullName -NoNewline
}

# Linux/macOS:
sed -i 's/{{PROJECT_NAME}}/My Project/g' AGENTS.md AI_MANDATE.md EXECUTION_AGENDA.md
```

---

## الخطوة 3 — املأ الملفات الخمسة (الأهم)

| الملف | املأه بـ |
|-------|---------|
| `EXECUTION_AGENDA.md` | مهام مشروعك الحقيقية — مرحلة بمرحلة، مع Quality Gate لكل مهمة |
| `RESEARCH_PROTOCOL.md` | أدوات/مصادر بحث مشروعك (توسيع قائمة المصادر في §3 حسب مجالك) |
| `CODE_MAP.md` | خريطة الملفات الفعلية: مجلدات، تبعيات، حساسية كل ملف |
| `CODE_PATTERNS.md` | أنماط من كودك الفعلي — اقرأ 3-4 ملفات مصدرية وانسخ أنماطها |
| `TEST_RUNNER.md` | أوامر build/test/run بتاعة مشروعك |
| `AGENTS.md` | نظرة عامة، أوامر الشغل، متطلبات التشغيل |

---

## الخطوة 4 — التحقق (امتحن النظام بنفسك)

1. افتح جلسة AI جديدة على المشروع.
2. المفروض يقرأ `AGENTS.md` تلقائياً → يشاور على الدستور.
3. المفروض يقيّم الجاهزية ثم **يطبع رسالة البيعة** ويسأل "أبدأ ولا لا؟".
4. قل "ابدأ" — المفروض يشتغل بالمهام من `EXECUTION_AGENDA.md`.

**لو ما طبعش البيعة** — القالب مش مركّب صح، راجع الخطوة 2 و3.

---

## قواعد التركيب

1. **لا تحذف `AI_MANDATE.md`** — هو قلب النظام.
2. **لا تعدّل القواعد** قبل أن تجرب النظام حياً أسبوعاً على الأقل.
3. **املأ الحقيقة بصدق** — الملفات اللي فيها مكان للإجابات (Truth State, Known Vulnerabilities) إياك تتركها "ممتلئة بالأوهام".
4. **لكل لغة:** `CODE_PATTERNS.md` و `TEST_RUNNER.md` يتغيران — الباقي ثابت.

---

## 🎨 عن الداشبورد والتصميم (مهم جداً)

- **أي داشبورد/واجهة في أي مشروع هي خاصّة بذلك المشروع فقط** — مبنية على محركاته وبياناته.
- **لا تنسخ داشبورد من مشروع قديم لمشروع جديد أبداً** — الادوات والكيانات تختلف.
- **عند الطلب: "اعمل تصميم/داشبورد"** — يُبنى **من الصفر** خصيصاً لهذا المشروع، ويقرأ بيانات المشروع **مباشرة** (بدل نسخ الملفات يدوياً).
- **مبدأ المصدر الوحيد يسري على الداشبورد أيضاً:** أي تغيير في `CHANGELOG.md` أو `EXECUTION_AGENDA.md` ينعكس تلقائياً — الداشبورد يقرأ من المصدر، ولا يُنسخ ولا يُزامَن يدوياً.

---

## لما تنسخ لمشروع آخر بعد الأول
بعد ما تحط النظام في مشروعك الأول وتكيّفه، انسخ النسخة المعدّلة (مش القالب الأصلي) — عشان تاخد كل الدروس اللي اتعلمتها.
